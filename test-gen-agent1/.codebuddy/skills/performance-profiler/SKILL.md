# 性能诊断器

针对本项目自身代码的性能分析技能，帮助 NPC 定位性能瓶颈（N+1 查询、大文件、慢接口）并给出优化方案。

## 适用场景

- 分析接口响应时间瓶颈
- 定位 N+1 数据库查询
- 大文件 / 大数据量读取与传输优化
- 前端列表加载性能分析
- 高并发场景下的吞吐优化

## 诊断流程

### 1. 定位热点

- 分析接口访问频率与响应时间（从 `app/routers/`、`app/services/` 入手）
- 查找循环内串行请求 / 查询的代码（N+1 模式）
- 检查大文件读取、全量加载列表的接口

### 2. 数据库查询分析

- 检查 ORM / 原生 SQL 是否在循环中执行
- 确认是否缺少批量查询、预加载（eager load）
- 分析索引使用情况（结合 database-schema-validator）
- 关注 `fetchall` 全量加载大表的风险

### 3. 并行化与缓存

- 串行请求改为 `asyncio.gather` / `Promise.all` 并发
- 高频只读数据引入缓存（内存 / Redis）
- 大列表引入分页 + 延迟加载
- 重复计算提取为可缓存结果

### 4. 前端性能

- 检查 `frontend/src/` 中列表是否一次性拉全量
- 前端大列表是否虚拟滚动
- 资源加载（图片、静态文件）是否需懒加载
- WebSocket 消息是否需批处理

### 5. 输出报告

输出性能诊断报告，包含：
- 瓶颈点位置（文件:行号）
- 影响说明（响应时间 / 资源占用）
- 优化建议与预期收益
- 优先级排序

## 项目约定

- 后端 FastAPI 异步框架，优先使用 `asyncio` 并发
- 前端 Vue3，优先使用组件级性能优化
- 项目自带性能测试模块（`app/performance/`），可复用其测试数据
- 性能优化需配合测试用例验证，避免破坏功能

## ✅ 验收标准

- [ ] 瓶颈点定位到具体文件:行号，有 profiling 数据或日志支撑
- [ ] 优化建议含预期收益与优先级排序
- [ ] N+1 查询、大文件读取、同步阻塞调用已逐一排查
- [ ] 建议的优化未破坏现有功能（配套测试仍通过）
- [ ] 报告区分「已验证瓶颈」与「疑似瓶颈」，不把猜测当结论
