# 测试用例生成器

针对本项目的测试用例生成技能，帮助 NPC 生成符合项目规范的自动化测试。

## 适用场景

- 为新的功能模块生成 pytest 测试
- 为已有功能补充边界/异常/安全测试
- 分析测试覆盖率并生成补测用例
- 为 API 接口生成契约测试

## 生成流程

### 1. 分析目标代码

阅读目标模块代码，理解：
- 业务逻辑与数据流
- 输入/输出参数与类型
- 依赖的服务和数据存储
- 错误处理与边界条件

### 2. 选择测试类型

根据功能特点选择合适的测试类型：

| 测试类型 | key | 适用场景 |
|---------|-----|---------|
| 功能测试 | `functional` | 核心业务逻辑验证 |
| 接口测试 | `api` | API 端点验证契约 |
| UI 测试 | `ui` | 前端界面交互 |
| 性能测试 | `performance` | 响应时间/吞吐量 |
| 安全测试 | `security` | 注入/越权/敏感信息 |
| 兼容性测试 | `compatibility` | 跨版本/平台兼容 |
| 可靠性测试 | `reliability` | 幂等/容错/稳定性 |

### 3. 编写测试用例

遵循以下规范：
- 使用 `pytest` 框架，测试文件命名为 `test_*.py`
- 测试函数命名：`test_{功能}_{场景}_{期望结果}`
- 使用项目统一的 `conftest.py` fixtures
- 每个测试包含清晰的三段式：准备、执行、断言
- 测试数据独立，不依赖外部服务（用 mock 或沙箱）

### 4. 验证与修复

- 运行 `pytest tests/ --tb=short` 验证
- 分析覆盖率，补充未覆盖分支
- 修复失败的测试，确保全部通过

## 项目约定

- 测试目录：`tests/`
- 测试基础配置：`tests/conftest.py`
- 测试框架：`pytest`（见 `requirements-dev.txt`）
- 统一响应格式断言：`{code, message, data}`

## ✅ 验收标准

- [ ] 测试文件位于 `tests/` 且命名为 `test_*.py`，复用 `tests/conftest.py` 夹具
- [ ] 测试函数命名符合 `test_{功能}_{场景}_{期望结果}`
- [ ] 已运行 `python3 -m pytest tests/ -q` 全部通过
- [ ] 断言使用统一响应格式 `{code, message, data}`
- [ ] 测试数据独立，不依赖外部服务与外部残余数据
- [ ] 新增用例确实提升了目标模块的覆盖率（可用 `--cov` 复核）
