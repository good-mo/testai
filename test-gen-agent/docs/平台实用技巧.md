## 📌 本项目推荐实践

1. **契约检查**：`python3 scripts/frontend_contract_check.py --check`
2. **路由冲突**：`python3 scripts/route_conflict_check.py --check`
3. **覆盖率门槛**：已在 `.cnb.yml` 开启（行 40% / 分支 20%），PR 未达标会阻塞合并
4. **数据库合并冲突检查**：`python3 scripts/merge_databases.py --check`，提前暴露跨库字段/索引冲突
5. **前端界面测试矩阵**：`python3 scripts/gen_frontend_matrix.py`，从前端源码自动抽取所有界面接口并生成用例（详见下方同名章节）
6. **前端冒烟分组**：PR 流水线先跑 `tests/test_frontend_*.py`（约 5 秒反馈），全量测试随后执行
7. **契约修复**：核对 `frontend/src/api/contracts.ts` 与后端实际路由，路径缺失补注册、方法不匹配改契约
8. **测试用例生成**：参照 `.codebuddy/skills/test-case-generator` 规范

## 🔒 发布风险门禁

`/api/insights/risk` 会按「复杂度 40 分 + 覆盖率缺口 30 分 + 缺陷密度 30 分」给每个模块打分，
输出 high / medium / low 三级清单。可作为发布前的回归门禁使用：

```bash
# 1. 拉取高风险清单
curl -s "http://localhost:8000/api/insights/risk?project_path=app" \
  | python3 -c "import sys,json; d=json.load(sys.stdin)['data']; \
print('high:', [m['file_path'] for m in d['high_risk']])"

# 2. 高风险模块未回归则不放行（退出码 1 即阻断流水线）
curl -s "http://localhost:8000/api/insights/risk?project_path=app" \
  | python3 -c "import sys,json; d=json.load(sys.stdin)['data']; \
sys.exit(1 if d['high_risk'] else 0)"
```

> 风险分阈值可用 `assess_risk(threshold_high=..., threshold_medium=...)` 调整，默认 60 / 30。

## 🛡 线上事故免责自查

`/api/insights/trace/prove?file_path=<文件>` 可一键调出某文件的历史执行记录，
用于回答「为什么没测出来」——区分是需求变更、环境异常、数据问题、代码回归，还是覆盖遗漏。

```bash
curl -s "http://localhost:8000/api/insights/trace/prove?file_path=app/defects/tracker.py"
```

排查顺序：先取证据 → 再看 `attribution` 归因 → 最后决定是补测、改流程还是提缺陷。

## 🔗 TAPD 缺陷一键转用例

一线测试最常做的动作是「TAPD 缺陷 → 补一条回归用例」。
用 `cnb-tapd-resource-fetcher` skill 解析链接，再把字段映射到缺陷库，人工只做最后确认：

1. **贴链接**：在 Issue/PR 评论里粘贴 TAPD 缺陷链接
   `https://www.tapd.cn/tapd_fe/{workspace_id}/bug/detail/{id}`
2. **拉字段**：skill 调用 `$CNB_API_ENDPOINT/tapd/reference/{workspace_id}/bug/{id}` 取回详情
3. **映射**：按下表转成缺陷记录 / 用例

   | TAPD 字段 | 本项目字段 | 说明 |
   |-----------|-----------|------|
   | `title` | `title` | 缺陷标题 |
   | `description` | `description` | 复现步骤原文保留 |
   | `severity` | `severity` | 需映射到 `blocker/critical/major/minor` |
   | `status` | `status` | 需映射到 `open/in_progress/fixed/closed/wont_fix` |
   | `module` | `file_path` | 落到具体源文件，风险预警才能按文件打分 |
   | `current_owner` | `assignee` | 处理人 |

4. **入库**：`python3 scripts/seed_defects.py` 走的是内置种子数据；
   外部缺陷请直接调 `POST /api/defects` 或 `app.defects.tracker.create_defect()` 落库。
5. **回写追溯**：缺陷对应的回归用例跑完后，用 `POST /api/insights/trace` 回写执行记录，
   下次线上复现时 `GET /api/insights/trace/prove` 才拿得出证据。

> 常见报错：`2000076` 未启用 TAPD 集成、`2000073` 未绑定 TAPD 账号 —— 都需要管理员/个人先配置，
> 不是脚本问题，不用去改代码。

## 🧭 前端界面测试矩阵（自动同步）

测试和前端是两拨人写的，必然会漂移：前端加了个页面、后端没接，手写测试永远不会知道，
直到用户在界面上点到才暴露成白屏或英文报错。

`scripts/gen_frontend_matrix.py` 把**前端源码**变成真相来源：

```bash
python3 scripts/gen_frontend_matrix.py            # 重新生成 tests/test_frontend_ui_full_matrix.py
python3 scripts/gen_frontend_matrix.py --inventory  # 只看清单统计，不写文件
python3 scripts/gen_frontend_matrix.py --check      # CI 用：清单与测试文件是否同步
```

它会做三件事：

1. 扫 `frontend/src/api/modules/**` 的 `MSR.get/post(...)` 调用点
2. 回溯 `frontend/src/api/requrls/**` 的 URL 常量，还原真实请求路径（含模板字符串、路径参数）
3. 按界面模块分组，生成 pytest 用例

于是**前端每加一个接口，重跑脚本就多一条用例；后端漏接，用例立刻变红**。

### 断言为什么分四档

不是所有 4xx 都该判失败，关键是区分「业务校验」和「功能没接通」：

| 档位 | 适用 | 断言 |
|------|------|------|
| `_list` | 列表/分页 | 必须有 `list` + `total`，缺了前端白屏 / 页码渲染成 NaN |
| `_count` | 模块树、各模块计数 | 成功时 data 必须是对象或数组 |
| `_dict` | 聚合类 | 成功时 data 必须是 dict |
| `_soft` | 增删改等动作 | 允许 4xx 业务校验，禁止 5xx |

**最核心的一条**：响应体里出现 `{"detail": ...}` 而没有 `code`，说明这个路由根本没走统一响应 ——
要么是没注册，要么是被 FastAPI 原生拦截了（比如 405）。这时前端只会弹一句看不懂的英文，
这才是真正要拦的「功能没接通」。传不存在的 id 返回 404「用户不存在」反而是**正确行为**，
前端本来就该弹提示。

### 顺带发现的真实 Bug

跑通这套矩阵时抓到三个前端真实会踩的坑，都已在本次修复：

1. **`POST /api/test/plugin/form/option` 返回 405**
   前端 `getPluginOptions` 用 POST 提交，后端只注册了 GET。点击插件配置下拉直接报错。
   已在 `method_compat.py` 补 POST 兼容。

2. **裸字符串请求体导致 500**
   前端 axios 拦截器对非 GET 请求执行 `config.data = { ...params }`；
   当调用点写成 `params: poolId`（字符串）时，请求体是裸字符串 `"xxx"` 而不是 `{"id": "xxx"}`。
   后端 `body.get("id")` 直接抛 `AttributeError`。
   已在 `app/core/response.py` 新增 `read_body()`，统一归一化三种形态
   （`{"id": x}` / `"x"` / `["a","b"]`），全项目 23 处 `_body` 已切换过去。

3. **`POST /api/scenario/statistics` 返回 `data: null`**
   前端 `scenarioTable.vue` 拿到结果直接 `res.find(...)`，null 会让 `find` 抛 TypeError，
   场景列表的通过率一栏永远渲染不出来。已改为返回 `[]`，与 `/api/case/statistics` 对齐。
