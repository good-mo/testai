## 一、用例管理模块

### 1.1 用例列表（GET /api/cases）

**功能**：分页列出测试用例，支持按状态、优先级、标签、关键词、测试类型过滤。

**参数**：
- `status`：用例状态（draft/review/approved/rejected/deprecated 等）
- `priority`：优先级（P0/P1/P2/P3）
- `tag`：标签过滤
- `search`：关键词模糊搜索
- `test_type`：测试类型（functional/api/ui/performance 等）
- `limit`：每页数量，默认 100
- `offset`：偏移量，默认 0

**业务规则**：
- 调用 `app.cases.repository.list_cases` 同步查询，通过 `asyncio.to_thread` 异步执行避免阻塞事件循环。
- 返回 `{cases: [...], total: len(cases)}`，total 为当前过滤条件下的实际数量（非总数）。

### 1.2 用例统计（GET /api/cases/stats）

**功能**：获取用例库统计信息（总数量、各状态/类型分布等）。

**业务规则**：
- 调用 `app.cases.repository.get_stats` 同步获取统计结果。
- 直接返回 JSON 格式的统计数据。

### 1.3 创建用例（POST /api/cases）

**功能**：创建一个新的测试用例。

**请求体参数**：
- `title`：用例标题（必填）
- `description`：用例描述
- `source_code`：源代码
- `test_code`：测试代码
- `file_path`：关联文件路径
- `tags`：标签列表
- `status`：状态，默认 `draft`
- `priority`：优先级，默认 `P2`
- `requirement_ref`：需求引用
- `test_type`：测试类型，默认 `functional`
- `structured_cases`：结构化用例列表

**业务规则**：
- 调用 `app.cases.repository.create_case` 同步创建。
- 直接返回创建的用例对象。

### 1.4 获取单个用例（GET /api/cases/{case_id}）

**功能**：按 ID 获取单个用例详情。

**业务规则**：
- 调用 `app.cases.repository.get_case` 查询。
- 用例不存在时返回 404 错误 `{error: "case {id} 不存在"}`。

### 1.5 更新用例（PUT /api/cases/{case_id}）

**功能**：更新用例的指定字段。

**请求体参数**：任意可更新的字段（非 null 的值会被更新）。

**业务规则**：
- 过滤掉值为 `null` 的字段，仅更新有效字段。
- 若更新 `test_type`，需特殊处理：将 test_type 写入 `metadata` 字段的 JSON 中，避免直接更新列。
- 若 `structured_cases` 不是 list 类型则忽略该字段。
- 调用 `update_case` 更新，抛出 `ValueError` 时返回 400。
- 用例不存在时返回 404。

### 1.6 删除用例（DELETE /api/cases/{case_id}）

**功能**：软删除用例，移入回收站。

**业务规则**：
- 调用 `app.cases.management.soft_delete_case` 软删除。
- 用例不存在时返回 404。
- 成功返回 `{deleted: true, trashed: true}`。

### 1.7 用例脑图（GET /api/cases/mindmap）

**功能**：获取用例的树形结构（脑图视图）。

**参数**：
- `project_filter`：项目过滤

**业务规则**：
- 调用 `app.cases.management.get_case_mindmap` 构建树形结构。
- 返回树形 JSON 数据。

### 1.8 导出用例（GET /api/cases/export）

**功能**：导出用例到文件。

**参数**：
- `format`：导出格式，支持 `excel`（CSV 格式）和 `mindmap`（JSON 格式）

**业务规则**：
- 先查询最多 1000 条用例。
- Excel 格式：生成 CSV 文件，临时文件方式下载。
- Mindmap 格式：生成 JSON 文件下载。
- 不支持的格式返回 400 错误。

### 1.9 用例回收站列表（GET /api/cases/trash）

**功能**：列出回收站中的用例。

**业务规则**：
- 调用 `app.cases.management.list_trash_cases`。
- 返回 `{trash: [...], total: n}`。

### 1.10 获取用例完整信息（GET /api/cases/{case_id}/full）

**功能**：获取用例的完整信息，含关联、依赖、评审、版本、变更、需求等。

**业务规则**：
- 调用 `app.cases.management.get_case_full_info`。
- 用例不存在时返回 404。

### 1.11 用例关联管理

#### 移除关联（DELETE /api/cases/{case_id}/relations/{related_id}）

#### 列出关联（GET /api/cases/{case_id}/relations）

### 1.12 用例导入（POST /api/cases/import）

**功能**：从 Excel 或 XMind 导入用例。

**请求体参数**：
- `format`：导入格式（`excel` 或 `mindmap`）
- `content`：文件内容
- `operator`：操作人

**业务规则**：
- Excel 格式调用 `import_cases_from_excel`。
- Mindmap 格式调用 `import_cases_from_xmind`。
- 不支持的格式返回 400。

### 1.13 用例评审流程

### 1.14 用例依赖管理

#### 列出依赖（GET /api/cases/{case_id}/dependencies）

### 1.15 回收站操作

#### 软删除到回收站（POST /api/cases/{case_id}/trash）
- 参数：`deleted_by`、`reason`
- 调用 `soft_delete_case`。

#### 从回收站恢复（POST /api/cases/{case_id}/restore）
- 参数：`operator`
- 调用 `restore_case`，不在回收站时返回 404。

#### 彻底删除（DELETE /api/cases/{case_id}/purge）
- 调用 `purge_case`，不存在时返回 404。

### 1.16 版本管理

- 调用 `list_case_versions`。

#### 获取指定版本（GET /api/cases/{case_id}/versions/{version}）
- 调用 `get_case_version`，版本不存在返回 404。

#### 回滚（POST /api/cases/{case_id}/rollback）
- 参数：`version`（整数）、`operator`
- 调用 `rollback_case`，版本不存在返回 404。

### 1.17 变更记录（GET /api/cases/{case_id}/changes）

**功能**：列出用例的变更历史。

**参数**：
- `limit`：默认 50

**业务规则**：
- 调用 `list_case_changes`，返回 `{changes: [...], total: n}`。

### 1.18 需求关联

#### 关联需求（POST /api/cases/{case_id}/requirements）
- 参数：`requirement_id`、`requirement_type`（默认 jira）、`requirement_title`、`requirement_url`

- 调用 `list_case_requirements`，返回 `{requirements: [...]}`。

## 二、缺陷管理模块

### 2.1 缺陷列表（GET /api/defects）

**功能**：分页列出缺陷，支持状态/严重程度过滤。

**参数**：
- `status`：缺陷状态
- `severity`：严重程度（critical/major/minor/trivial）
- `limit`：默认 100
- `offset`：默认 0

**业务规则**：
- 调用 `app.defects.tracker.list_defects` 获取缺陷列表。
- 同时调用 `get_stats` 获取统计信息。
- 返回 `{defects: [...], stats: {...}, total: n}`。

### 2.2 创建缺陷（POST /api/defects）

**请求体参数**：
- `title`：缺陷标题（必填）
- `description`：缺陷描述
- `severity`：严重程度，默认 `major`
- `file_path`：关联文件路径
- `test_case_id`：关联测试用例 ID
- `error_snippet`：错误代码片段
- `assignee`：处理人

**业务规则**：
- 调用 `app.defects.tracker.create_defect` 同步创建。

### 2.3 获取单个缺陷（GET /api/defects/{defect_id}）

**业务规则**：
- 调用 `get_defect`，不存在返回 404。

### 2.4 更新缺陷（PUT /api/defects/{defect_id}）

**请求体参数**：任意可更新的非 null 字段。

**业务规则**：
- 过滤 null 值字段后调用 `update_defect`。
- 抛出 ValueError 返回 400。
- 缺陷不存在返回 404。

### 2.5 彻底删除缺陷（DELETE /api/defects/{defect_id}）

**业务规则**：
- 调用 `delete_defect(defect_id, permanent=True)` 彻底删除。

### 2.6 缺陷回收站

#### 软删除到回收站（POST /api/defects/{defect_id}/trash）
- 调用 `soft_delete_defect`。

#### 恢复（POST /api/defects/{defect_id}/restore）
- 调用 `restore_defect`，不在回收站返回 404。

#### 彻底删除（DELETE /api/defects/trash/{defect_id}）
- 调用 `purge_defect`。

#### 回收站列表（GET /api/defects/trash）
- 调用 `list_trash_defects` 和 `count_trash_defects`。

#### 批量恢复（POST /api/defects/trash/recover）
- 参数：`ids`（缺陷 ID 列表）
- 遍历调用 `restore_defect`，统计成功数量。

#### 批量彻底删除（POST /api/defects/trash/batch-delete）
- 参数：`ids`
- 遍历调用 `purge_defect`，统计成功数量。

### 4.1 测试计划 CRUD

#### 分页列表（POST /test-plan/page）
- 参数：`keyword`、`pageSize`、`current`
- 调用 `test_plan_store.list_plans` 获取计划。
- 批量获取统计信息（executionRate/passRate/caseCount）。
- 返回 `{list, total, pageSize, current}`。

#### 创建（POST /test-plan/add）
- 参数：`name`（默认"未命名测试计划"）、`description`、`priority`（默认 P2）、`moduleId`（默认 root）、`createUser`（默认 admin）
- 调用 `create_plan`。

#### 更新（POST /test-plan/update）
- 参数：`id`、`name`、`description`、`priority`、`status`、`startTime`、`endTime`
- 将前端字段名映射为后端字段名（startTime→start_time 等）。
- 计划不存在返回 404。

#### 删除（POST /test-plan/delete）
- 参数：`id`

#### 批量删除（POST /test-plan/batch-delete）
- 参数：`ids`

#### 归档（POST /test-plan/archived）
- 参数：`id`
- 调用 `archive_plan`。

#### 批量归档（POST /test-plan/batch-archived）
- 参数：`ids`

#### 复制（POST /test-plan/copy）
- 参数：`id`
- 复制为 `{原名称} (副本)`。
- 不存在返回 404。

#### 批量复制（POST /test-plan/batch-copy）
- 参数：`ids`

#### 统计（GET /test-plan/getCount）
- 返回计划总数。
